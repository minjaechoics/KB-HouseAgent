## 2. 데이터 분류 원칙 (발표 시 슬라이드 1장으로 쓰기 좋음)

시스템은 모든 데이터를 아래 6가지 중 하나로 명확히 분류합니다. "이 숫자가
실제 관측인지, 모델 추정인지, 가정인지"를 항상 구분해서 보여주는 것이
이 프로젝트의 핵심 설계 원칙입니다.

1. **공식 원천 관측** — 정부·공공기관 API/CSV의 실거래·시설·통계 (예: RTMS, R-ONE)
2. **사용자 제공 원천** — 합법적으로 확보해 제공한 금융상품·매물 자료 (예: KB 대출상품, 팔달구 매물 PDF)
3. **파생 관측** — 원천을 정규화·지오코딩·집계한 값
4. **모델 추정** — 관측값에서 예측한 값 (예: 보증사고 확률, 집값 전망)
5. **시나리오 가정** — 정답 라벨이 없어 사용자가 해석해야 하는 가정값 (예: 선순위보증금 추정)
6. **합성 실험** — 분포 보존·다양성 검증용으로 생성한 비운영 데이터 (현재 서비스에는 미사용)

### 3.7 (참고) 과거 합성·증강 실험 — 현재 서비스 미사용

`src/data_augmentation/`에 남아있는 과거 실험 코드입니다. 발표에서 "실험해봤지만
현재 운영에는 안 쓴다"는 점을 명확히 구분해서 말하는 게 좋습니다.

- `multi-source-conditional-bootstrap-v2` 실험: 20,000건·208열 합성 매물 생성
- 방법: 주택유형×거래유형 18개 조합 목표 배정 → 지역·유형 조건부 RTMS 앵커 복원추출 →
  18개월 반감기 지수가중 최신성 반영 → log-normal 면적 교란 → 잔차 재표본화 매매가 모형
- 당시 가격모형: 로그 ㎡당가격 R²=0.7552, MdAPE 17.68% (단, 서울 편중 심함)
- **현재 상태**: 이 실험 데이터는 활성 DB(948건)와 별개이며 운영에 쓰이지 않음

### 3.8 (참고) 외부 매물 피드 / CODEF — 스키마만 존재, 미사용

- **외부 매물 피드(Bright Data 등)**: `listing_sources`, `live_property_listings`, `feed_sync_runs` 테이블 스키마는 준비돼 있으나 현재 활성 행 0건. 권리(제휴 계약/이용허락) 확인 전까지는 수집하지 않는다는 원칙 때문.
- **KB부동산 데이터허브 시세**: 이용약관상 크롤링 금지 조항 때문에 매물 DB로 치환하지 않음(`KB_DATA_LICENSED=false` 기본값).
- **CODEF**: sandbox/test 흐름만 연결, 실제 금융기관 승인·잔액 데이터 아님, 부동산 가격 산정에 미사용.

## 5. 발표에서 짚으면 좋은 한계·주의사항 요약

- 활성 매물(948건)은 실시간 매물 재고가 아니라 PDF 기반 프로토타입이며 좌표는 분석용 대표점
- 임대인 총자산·건물별 실제 선순위보증금은 "정답 라벨"이 없어 전부 확률분포/시나리오로 제시(단정 아님)
- 전세보증사고 위험모형은 로컬 재학습이 아니라 공개 논문 회귀계수를 이전한 모형
- R-ONE과 RTMS는 집계기준이 달라 같은 지표로 혼동하면 안 됨
- 과거 20,000건 합성 실험 데이터는 현재 운영 DB와 무관(별도 실험 산출물)
- 외부 매물 피드·KB 시세·CODEF는 권리 미확보/약관상 제약으로 현재 미사용
