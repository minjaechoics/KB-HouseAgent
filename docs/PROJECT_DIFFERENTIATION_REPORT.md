# 프로젝트 차별점 분석 보고서

작성일: 2026-07-29
대상: KB국민은행 AI Challenge 제출 프로젝트
팀명: 똘똘한최

## 1. 개요

본 보고서는 청년 주거 의사결정 과정을 **정보 수집 → 해석 → 예측 → 결정**의 4단계
파이프라인으로 재정의하고, 각 단계에서 청년이 실제로 겪는 실패와 이 프로젝트가
제시하는 기술적 차별점을 정리한다. 목적은 발표에서 "무엇을 만들었는가"가 아니라
"왜 이 방식이 다른가"를 근거를 들어 설명하는 데 있다.

## 2. 문제 정의: 청년 주거 의사결정의 4단계와 각 단계의 실패

주택을 구하는 과정은 정보를 모으고, 모은 정보를 해석하고, 그 결정이 미래에
미칠 영향을 예측하고, 여러 후보 중 하나를 고르는 4단계로 볼 수 있다. 현재
청년은 이 네 단계 모두에서 막힌다.

1. **정보 수집의 파편화**: 청년이 주택을 구할 때 매물 검색, 금융상품 자격,
   전세사기 위험, 통근 여건, 장기 자산 계획을 각각 다른 서비스에서 따로
   확인하고 스스로 통합해야 한다.
2. **해석의 부재 — 전세사기 리스크의 사전 예측 불가**: 등기부등본,
   선순위임차보증금, 근저당 등 계약 전 위험 신호를 청년 개인이 해석하기
   어렵고, 이를 사전에 치밀하게 계산해 보여주는 방법이 없다. 특히
   다가구주택은 건물 전체가 집주인 1인 명의의 단독 등기라 호실별 선순위
   임차보증금이 등기부에 나타나지 않으며, 임차인 후보가 계약 전에 이를
   확인할 공개된 방법 자체가 없다.
3. **예측의 부재 — 장기 계획 시뮬레이션 불가**: 전세가 유리한지 월세가
   유리한지, 특정 주택에 거주할 때 장기적으로 얼마가 드는지를 계획할
   도구가 없다.
4. **결정의 부재 — 다기준 비교와 최적화 불가**: 정보와 위험, 미래 비용을
   전부 파악하더라도, 예산과 대출 조건까지 얽힌 여러 매물·금융상품·대출액
   조합 중 무엇이 최선인지 스스로 비교할 방법이 없다.

## 3. 단계별 차별점

### 3.1 정보 수집 → 조건이 잠긴 에이전트

일반적인 통합검색 챗봇은 차별점이 되지 못한다. 다수의 참가팀이 유사한 형태를
제시할 것이기 때문이다. 이 프로젝트의 차별점은 **검색 범위가 구조적으로 잠겨
있다는 점**이다.

```
U0 (초기 교집합) = 지역 ∩ 거래유형 ∩ 가격 ∩ 면적 ∩ 예산
U1 (추가 검색 범위) = U0 ∩ 승인된 AI 조건
```

AI는 대화 중 추정한 조건을 임의로 적용하지 않고, 사용자가 UI에서 명시적으로
승인한 조건만 `U0` 내부로 좁히는 데 사용한다. 즉 AI가 초기 지역이나 예산 범위를
스스로 넓히는 경로가 없다. 이는 "AI가 판단 범위를 임의로 확장했다"는 신뢰 사고를
구조적으로 차단하는 설계이며, 금융 서비스에서 요구되는 통제 가능성과 직결된다.

관련 구현: `src/server/property_search.py`, `src/agent/harness.py`

### 3.2 해석 → 단일 점수가 아닌 확률모델 결합

기존 서비스 다수는 등기부등본을 그대로 노출하거나, "전세가율 80% 초과 시 위험"과
같은 단일 규칙으로 위험 여부를 판정한다. 이 프로젝트는 세 개의 독립된 확률모델을
매물 단위로 결합한다.

| 모델 | 방법 | 산출 |
|---|---|---|
| 전세사기 위험도 | HUG·HF 실제 사고 데이터 기반 학습, 확률 보정 | 보정된 사고 확률, 등급, 기여 요인 |
| 집주인 총자산 비율 | 호실 수·건물가치·가계금융복지조사 조건부 자산분포를 Monte Carlo로 결합 | 특정 개인 자산 추정이 아닌 확률분포(P10/P50/P90) |
| 선순위 임차보증금 | 건축HUB 등록 호수와 동일 법정동 RTMS 임대차 분포를 결합, 다른 점유 호실 전원을 선순위로 보는 보수적 시나리오 | 보수적 상한 추정치(`scenario_only`) |

특히 선순위 임차보증금 모델은 다가구주택 특유의 구조적 정보 비대칭(구분등기가
없어 시장에 확인 방법 자체가 없는 문제)을 겨냥한다는 점에서, 대부분의 경쟁
서비스가 아예 시도하지 않는 영역이다.

세 모델의 결과는 단정적 위험 여부가 아니라 확률분포와 불확실성 표시로 제공되며,
`fraud_score`는 검색 필터가 아니라 설명·정렬 지표로만 사용한다. 확신 없는 값을
확신 있는 값처럼 보여주지 않는 이 정직성이 일반적인 규칙 기반 체크리스트
서비스와의 실질적인 차이다.

관련 구현: `src/fraud_risk/`, `src/owner_asset_ratio/`, `src/senior_deposit/`
관련 문서: `FRAUD_RISK_ACTUAL_LABEL_MODEL.md`, `docs/OWNER_ASSET_RATIO_PIPELINE.md`,
`docs/SENIOR_DEPOSIT_MODEL.md`

### 3.3 예측 → 생애주기 비교 시뮬레이션

대출 한도 계산기류 서비스는 시점 하나의 숫자만 제공한다. 이 프로젝트는 거래유형
(매매·전세·월세)과 금융상품을 교체하면서, 소득상승률·물가상승률·생활비·자녀
양육비 곡선·주택가격 경로를 동일하게 고정한 상태에서 순자산 경로를 나란히
비교한다. 여러 경로에 동일한 난수 시드를 공유해, 상품 간 결과 차이가 우연이
아니라 금리·한도·상환구조의 차이에서만 나오도록 설계했다. 즉 "지금 대출이 얼마
나오는가"가 아니라 "이 선택을 10~20년 유지했을 때 내 순자산이 어떻게 달라지는가"를
분포(P10~P90)와 현금고갈확률, CVaR 5% 등으로 답한다.

관련 구현: `src/simulation/`, `src/report/budget.py`, `src/report/service.py`
관련 문서: `docs/PROBABILISTIC_DECISION_ENGINE.md`, `ASSET_SIMULATION_AND_WEB_SEARCH.md`

> 구현 현황: 매물 상세 리포트 화면뿐 아니라 대화형 질문("전세가 좋을까
> 월세가 좋을까")에 대응하는 `qa_lease_compare` 의도도 동일한 Monte Carlo
> 엔진을 직접 호출한다. 특정 매물이 없으면 적정예산 기반 대표 시나리오임을
> 명시해 답한다.

### 3.4 결정 → 근거 기반 조합 최적화

여러 매물, 여러 금융상품, 여러 대출액을 사람이 손으로 비교해 "최선의 조합"을
고르는 것은 사실상 불가능하다. 이 프로젝트는 이를 제약충족 다목적 최적화
문제로 정식화한다.

- **하드 제약**: 계약 필요 현금 ≤ (보유자산 − 6개월 비상자금) + 대출, 상품별
  공개 한도·담보비율, 월 상환액 ≤ 월 가처분소득 35%
- **목적함수**: 자산·부담·안전·통근·유동성·부채기피 6개 축을 사용자 성향
  (안정형·균형형·성장형)으로 가중합
- 매물×금융상품×대출액 조합을 SciPy HiGHS MILP 솔버로 계산하고, 단일 정답
  대신 지배당하지 않는 파레토 대표점(내 성향/10년 순자산 우선/월부담
  최소/안전 우선/통근 우선)을 제시

이는 단순 정렬·필터가 아니라 실제 제약충족 다목적 최적화이며, 추천 결과가
왜 최선인지에 대한 근거(트레이드오프)를 함께 제공한다는 점에서 일반적인
추천 랭킹과 다르다.

관련 구현: `src/optimization/service.py`
관련 문서: `docs/PROBABILISTIC_DECISION_ENGINE.md` 3장

> 구현 현황: `goal_best_affordable` 의도로 연결되어 대화형 질문("수원에서
> 내 예산으로 대출 포함해서 제일 좋은 집이 뭐야")에 `finance_search →
> property_search → optimize_housing_choices` 순서로 바로 응답한다. 같은
> 패턴으로 "여기 말고 예산 맞는 다른 동네"에 답하는 `goal_alternative_areas`,
> "지금 살까 1~2년 기다릴까"에 실거래 시계열 전망과 대기 비용을 함께
> 비교하는 `qa_buy_or_wait`도 함께 추가되어, 4단계 결정 파이프라인이 대화형
> 질문으로 완전히 열렸다.

## 4. 네 단계를 관통하는 설계 철학

개별 기능보다 상위에 있는 차별점은 다음의 일관된 태도다.

> 확신이 없을 때는 범위를 넓히지 않고 되묻는다.
> 위험은 단정하지 않고 확률분포로 보여준다.
> 미래는 단일 숫자가 아니라 불확실성 구간으로 예측한다.
> 추천은 결과만 제시하지 않고 왜 최선인지 근거를 남긴다.

정보 수집(조건 잠금), 해석(확률모델), 예측(생애주기 시뮬레이션), 결정(근거
있는 최적화) 네 영역 모두에 동일한 보수성과 설명 가능성 원칙이 적용되어 있다.
이 일관성은 개별 기능을 단순 합산한 것보다 강한 근거가 된다.

## 5. 결론

네 단계 각각에 대한 대응은 다음 한 문장으로 요약된다.

- 정보 수집의 파편화 → 사용자가 승인한 조건만 반영하는, 임의로 확장하지 않는
  에이전트
- 해석의 부재(전세사기 리스크) → 실제 사고 데이터로 보정된 확률모델 3종의
  결합과 불확실성 공개, 특히 다가구주택 선순위보증금이라는 시장에 없는 영역
- 예측의 부재(장기 계획) → 거래유형·금융상품을 교체 가능한 생애주기
  순자산 시뮬레이션
- 결정의 부재(다기준 비교) → 하드 제약과 사용자 성향을 반영한 MILP 파레토
  최적화

네 대응 모두를 관통하는 공통 원칙은 "정직한 불확실성과 통제된 자동화"이며,
이는 금융 도메인에서 요구되는 신뢰 요건과 직접적으로 부합한다. 3·4단계의
엔진은 매물 리포트 화면뿐 아니라 대화형 질문(`qa_lease_compare`,
`goal_best_affordable`, `goal_alternative_areas`, `qa_buy_or_wait`)에도
연결되어, 발표에서 청년이 실제로 물어볼 법한 질문을 그대로 시연할 수 있다.
