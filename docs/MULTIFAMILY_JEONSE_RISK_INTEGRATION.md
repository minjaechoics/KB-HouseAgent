# 다가구 전세 위험도 통합 설계

## 1. 목적

이 문서는 다가구주택 전세 매물에 적용되는 두 확률 모델과 화면 표시 위치를 설명한다.

핵심 원칙은 다음과 같다.

- 전세사기 위험도 점수는 `선택 전세보증금 ÷ 추정 집주인 총자산`으로 계산한다.
- 기존 임차인의 선순위 보증금 추정치는 별도 계약 확인지표로 표시한다.
- 두 금액을 임의로 합쳐 하나의 수치처럼 표시하지 않는다.
- 통계 추정치를 특정 집주인의 실제 자산이나 확정 선순위 보증금으로 표현하지 않는다.
- 계약 탭과 최종평가는 동일한 위험도 점수와 등급을 사용한다.

## 2. 적용 범위

두 모델 모두 `다가구주택`에만 적용된다.

| 모델 | 거래유형 | 비적용 사례 |
|---|---|---|
| 집주인 총자산 비율 모델 | 전세 | 월세, 매매, 아파트, 오피스텔 등 |
| 선순위 보증금 추정 모델 | 전세·월세 | 매매, 다가구가 아닌 주택 |

건축물대장과 도로명주소가 정확히 일치하면 정확 매칭 특성을 사용한다. 정확 매칭이 없으면 다른 건물을 유사 매칭하지 않고, 선택 매물에 기록된 면적·층수·세대수 등의 속성만 사용해 저신뢰 추정을 수행한다.

## 3. 모델 A: 집주인 총자산 비율

### 3.1 위험도 수식

```text
R = 선택한 호실의 전세보증금 / 추정 집주인 총자산
```

기본 등급은 다음과 같다.

| 중앙 추정 비율 | 등급 |
|---:|---|
| 60% 미만 | 낮음 |
| 60% 이상 80% 미만 | 주의 |
| 80% 이상 | 위험 |

중앙값만 보여주지 않고 P10·P50·P90과 `R > 80%` 확률도 함께 계산한다.

### 3.2 사용 데이터

- 건축HUB 건축물대장: 용도, 면적, 층수, 공부상 호실 수 등
- 국토교통부 단독·다가구 전월세 실거래: 임차보증금 분포
- 국토교통부 단독·다가구 매매 실거래: 건물가치 분포
- 가계금융복지조사: 임대인 가구의 조건부 기타자산·부채 분포

### 3.3 확률 추정

Monte Carlo 경로마다 다음을 표본 추출한다.

1. 공부상 호실 수가 없으면 호실 수 모델로 추정한다.
2. 입주율을 베타분포에서 추출한다.
3. 지역·면적 조건부 임대차 보증금 분포를 추출한다.
4. 지역·건물 특성 조건부 건물가치 분포를 추출한다.
5. 가계금융복지조사 가중치를 반영한 임대인 기타자산 비율을 추출한다.
6. 선택 전세보증금을 각 경로의 총자산으로 나누어 위험비율 분포를 만든다.

특정 집주인의 실제 계좌, 다른 부동산 보유내역 또는 금융자산을 조회한 결과가 아니다.

대화형 상세 리포트는 응답시간을 위해 5,000개 경로를 사용한다. 전용 연구 API에서는 최대 100,000개 경로까지 지정할 수 있다. 팔달구 프로토타입의 5,000개·20,000개 경로 비교에서 중앙 비율과 위험등급은 동일했으며, 실제 화면은 실행한 경로 수를 근거 설명에 표시한다.

### 3.4 코드와 화면 위치

- 추론 구현: `src/owner_asset_ratio/simulation.py`
- 서비스 연결: `src/owner_asset_ratio/service.py`
- 리포트 위험근거 생성: `src/report/service.py`
- 화면 표시: 상세 리포트의 `계약/안전` 탭
  - `전세금/집주인 총자산 위험도`
  - `집주인 총자산 추정 모델`
  - `어떻게 추정되었나요?`

## 4. 모델 B: 선순위 보증금 추정

### 4.1 추정 대상

선택한 호실을 제외한 기존 임차인의 보증금 총합을 추정한다.

```text
기존 선순위 보증금 총합
= Σ(기존 입주 호실별 추정 보증금)
```

결과는 P10·P50·P90과 보수적인 P95를 표시한다. 선택한 사용자의 보증금은 이 값에 포함하지 않고 별도 표시한다.

### 4.2 코드와 화면 위치

- 추론 구현: `src/senior_deposit/`
- 서비스 연결: `src/senior_deposit/service.py`
- 화면 표시: 상세 리포트의 `계약/안전` 탭
  - `기존 임차보증금 추정`
  - `기존 임차보증금 · 보수 P95`
  - `선택 매물의 내 보증금`

법적 확정값은 전입세대확인서, 확정일자 현황과 실제 임대차계약 자료로 다시 확인해야 한다.

## 5. 두 모델을 합치지 않는 이유

선순위 보증금과 선택 전세보증금은 서로 다른 계약 노출이다. 선순위 추정치를 위험도 수식의 분자에 자동 합산하면 사용자가 지정한 `전세보증금 ÷ 집주인 총자산` 정의가 바뀌고, 추정오차도 중복 전파될 수 있다.

따라서 응답에는 다음 플래그를 남긴다.

```json
{
  "senior_deposit_added_to_ratio": false,
  "owner_assets_are_observed": false,
  "official_verification_required": true
}
```

## 6. 계약 탭과 최종평가의 일관성

리포트 생성 시 총자산 비율 모델이 사용 가능하면 해당 점수로 리포트 내부 위험점수를 교체한다. 데이터베이스 원본 점수는 변경하지 않는다.

최종평가는 계약 탭의 `risk_explanation.model_evidence`를 그대로 읽는다. 등급이 `위험`이면 다음 강제 규칙이 적용된다.

- 최종 추천을 `avoid`로 고정한다.
- “계약안전이 우수하다”, “보증금 반환위험이 낮다” 같은 상충 표현을 제거한다.
- 실제 자산·선순위 권리·보증가입 가능 여부 확인을 행동 항목으로 제시한다.

## 7. 주변 안전시설 데이터

- 치안센터·파출소: 경기도 파출소·지구대 현황 Open API
- 소방서: 경기도 소방·경찰·지구대·치안센터 현황 Open API
- 편의점: 생활안전지도 IF_0039 캐시를 우선하고, 사용할 수 없으면 NAVER 지역검색 결과를 거리 재검증해 보완한다.

정규화된 경기 데이터 캐시는 다음 위치에 저장된다.

```text
data/generated/safety_geocoded/police_gg.csv
data/generated/safety_geocoded/fire_station_gg.csv
```

생활안전지도 인증키가 미등록 상태를 반환하는 경우에는 숫자를 임의 생성하지 않는다.

## 8. 검증

다음 자동 검증을 포함한다.

- 선순위 보증금 분포가 변해도 선택 보증금/총자산 비율은 변하지 않는지 확인
- 선택 보증금과 기존 선순위 보증금이 별도 필드인지 확인
- 정확 주소 미매칭 시 다른 건물로 유사 매칭하지 않는지 확인
- 위험 등급인데 최종평가가 안전하다고 말하지 않는지 확인
- UI에 추정 근거, 금융상품 미적용 상태, 그래프 축 제목이 있는지 확인
- 로딩 화면이 이미지가 아닌 DOM·CSS·`requestAnimationFrame` 기반인지 확인

팔달구 프로토타입 전세 매물의 실제 통합 검증에서는 선택 보증금 4,500만원, 총자산 비율 중앙값 4.0%, 선순위 보증금 중앙 추정 약 8,883만원이 각각 별도 값으로 반환됐다.

## 9. 해석상 주의

- 낮은 비율이 임대인의 선의를 보증하지 않는다.
- 집주인 실제 총자산과 채무는 등기부, 납세증명, 금융기관 심사 등을 통해 별도로 확인해야 한다.
- 선순위 보증금은 통계 추정이므로 계약 전 공식 자료로 검증해야 한다.
- 보증기관의 가입 가능 여부는 금액 기준 예비검사만으로 확정할 수 없다.
