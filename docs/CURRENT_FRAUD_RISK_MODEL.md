# 현재 전세 보증사고 위험도 판단 모델

작성 기준일: 2026-07-22  
운영 메타데이터: `models/fraud_risk_model.json`  
핵심 추론 코드: `src/fraud_risk/infer.py`

## 1. 한 줄 결론

현재 `fraud_score`는 **HF 실제 보증계약 453,122건에서 공개된 이항 로짓 계수를
현재 전세 매물 피처에 적용하고, 평균 사고확률을 HF 표본 사고율 4.98784%에 맞춰
절편 보정한 보증사고 추정확률**이다.

따라서 이 점수는 다음과 같지 않다.

- 집주인이 전세사기 범죄자일 확률
- 해당 매물에서 보증금을 잃을 확정 확률
- 등기부·체납·신탁·선순위 임차인 조사를 대신하는 안전 인증
- 이 저장소의 합성 `fraud_label`을 학습해서 얻은 확률

현재 모델 종류는 다음 값으로 고정되어 있다.

```json
{
  "kind": "published_hf_actual_label_transfer",
  "label_source_status": "actual_labels_external_published_coefficients"
}
```

즉, **실제 사고 라벨로 외부에서 추정된 공개계수 이식 모델**이다. 로컬에서 실제
HF/HUG 계약 원시 레코드로 계수를 다시 학습한 모델은 아직 아니다.

## 2. 운영 처리 흐름

```text
전세 매물 레코드
    │
    ├─ 주택가격·보증금·선순위채권
    ├─ 주택유형·지역·소유자유형
    ├─ 가격산정방식·월세·전세대출
    └─ 가격지수·금리 변화
    │
    ▼
HF 정의에 맞는 22개 피처 생성
    │
    ▼
공개 이항 로짓 계수 적용
z_raw = -40.347 + Σ(βᵢxᵢ)
    │
    ▼
현재 포트폴리오 사전확률 보정
z = z_raw + 3.6794697167
    │
    ▼
p = 1 / (1 + exp(-z))
    │
    ├─ p < 2.38095%             → 낮음
    ├─ 2.38095% ≤ p < 4.76190% → 주의
    └─ p ≥ 4.76190%             → 위험
    │
    ▼
properties.fraud_score 저장
    │
    ├─ 매물 상세화면 위험도 표시
    └─ 위험도 오름차순/내림차순 정렬
       ※ 검색 WHERE 필터로는 사용하지 않음
```

## 3. 모델이 예측하는 대상

### 3.1 라벨의 의미

외부 연구의 종속변수는 보증계약의 **전세보증 사고 발생 여부**다. 일반적으로 계약
종료 후 임대인이 보증금을 반환하지 않거나 경·공매 후 보증금을 회수하지 못해
보증사고로 처리된 경우를 의미한다.

현재 점수의 올바른 표현은 다음과 같다.

> HF 보증가입 표본과 공개모형 정의에 조건부인 보증사고 추정확률

### 3.2 외부 연구 표본

운영 메타데이터에 기록된 표본은 다음과 같다.

| 항목 | 값 |
|---|---:|
| 보증계약 | 453,122건 |
| 사고 | 22,601건 |
| 관측 사고율 | 4.98784% |
| 보증 발급기간 | 2019-01~2023-12 |
| 결과 관찰 종료 | 2024-12 |
| 범위 | 서울·경기·인천 보증계약 |

출처는 안선영·이상엽(2025), 「전세보증금 미반환에 영향을 미치는 주요요인
연구」이며 운영 메타데이터에는 DOI
`https://doi.org/10.52344/hfr.2025.9.2.47`이 저장되어 있다.

## 4. 확률 계산식

### 4.1 원 로짓

각 매물에서 피처 벡터 `x`를 만들고 다음 값을 계산한다.

```text
z_raw = -40.347 + β₁x₁ + β₂x₂ + ... + β₂₂x₂₂
```

### 4.2 현재 포트폴리오 절편 보정

논문 표에는 발급연도 통제계수가 전부 공개되어 있지 않다. 원 절편을 그대로 확률로
해석하지 않고, 현재 전세 매물 33,333건의 평균 예측확률이 연구표본 사고율과 같아지도록
이분법으로 절편 이동값을 구했다.

```text
logit_shift = +3.679469716695711
z = z_raw + logit_shift
mean(sigmoid(z)) = 22,601 / 453,122 = 0.0498783992
```

이 보정은 순위를 바꾸지 않고 전체 확률 수준만 이동한다. 현재 서비스 포트폴리오의
실제 사고율을 관찰해서 보정한 것이 아니라 **외부 기준 사고율에 맞춘 prior transfer**다.

### 4.3 최종 확률

```text
fraud_score = sigmoid(z) = 1 / (1 + exp(-z))
```

수치 오버플로를 피하기 위해 양수·음수 로짓을 나누어 안정적인 sigmoid 구현을 쓴다.

### 5.1 HF 모형의 부채비율

확률모형에 들어가는 부채비율은 다음과 같다.

```text
HF 부채비율(%)
= (내 보증금 + 선순위보증금 + 선순위근저당) / 주택가격 × 100
```

- 주택가격: `market_price_manwon`
- 선순위채권: 직접값이 없으면 `senior_deposit_sum_manwon + senior_mortgage_manwon`
- 60% 미만이 기준범주
- 90% 이상이면 로짓에 `+3.399`가 더해진다.

계수만 승산비로 바꾸면 `exp(3.399) ≈ 29.9`이지만, 최종 확률은 보증금 규모·주택유형·
지역 등 다른 피처와 절편 보정을 모두 적용한 뒤 결정된다.

### 5.2 선순위채권 계수가 음수인 이유에 대한 주의

`has_senior_claim=-0.737`을 “선순위채권이 있으면 더 안전하다”로 해석하면 안 된다.
외부 연구 표본은 보증가입 심사를 통과한 계약에 조건부이고 선순위채권 한도 제한이
있다. 금융기관·보증기관 심사를 통과한 표본의 선택효과가 섞였을 수 있다.

## 6. 현재 등급과 비용 임계값

### 6.1 비용 정책

현재 정책은 사고 매물을 놓치는 비용을 정상 매물 오경보보다 20배 크게 둔다.

```text
C_FN = 20  # 사고인데 안전하다고 판단
C_FP = 1   # 정상인데 위험하다고 판단

위험 임계값
= C_FP / (C_FP + C_FN)
= 1 / 21
= 0.0476190476
```

20:1은 연구에서 산출된 사회적 비용이 아니라 제품의 보수적 운영 가정이다.

### 6.2 화면 등급

| 등급 | 조건 |
|---|---:|
| 낮음 | `fraud_score < 0.0238095` |
| 주의 | `0.0238095 ≤ fraud_score < 0.0476190` |
| 위험 | `fraud_score ≥ 0.0476190` |

`주의`의 경계는 위험 임계값의 절반이다. 이는 별도 학습된 세 등급 분류기가 아니라
UI 설명을 위한 구간이다.

## 7. 현재 DB 적용 상태

`src/db/build_db.py`는 `lease_type='전세'`인 행에만 점수를 계산한다. 매매·월세의
`fraud_score`는 `NULL`로 유지한다.

| 항목 | 값 |
|---|---:|
| 전체 매물 | 100,000건 |
| 점수화된 전세 매물 | 33,333건 |
| 평균 점수 | 0.0498784 |
| 최소 | 약 0.00000034 |
| 최대 | 약 0.983058 |
| 낮음 | 21,673건, 약 65.02% |
| 주의 | 3,874건, 약 11.62% |
| 위험 | 7,786건, 약 23.36% |

평균 점수가 4.99%라고 위험 등급 비율도 4.99%인 것은 아니다. 매우 낮은 점수의
다수 매물과 높은 점수의 일부 매물이 섞인 비대칭 분포이고, 위험 경계도 평균보다
약간 낮은 4.7619%이기 때문이다.

현재 매물은 실제 광고가 아니라 실거래 분포를 바탕으로 생성한 합성 매물이다. 따라서
위 분포는 운영 파이프라인 검증값이지 실제 전국 전세매물의 위험분포 통계가 아니다.

## 8. 검색·정렬·상세화면에서의 사용

### 8.1 검색 필터가 아님

현재 위험도는 초기 조건이나 AI 추가 조건의 `WHERE fraud_score < ...` 필터로 사용하지
않는다. 사용자가 “안전한 순서”를 요청하면 동일한 조건 교집합 안에서 다음 정렬만 한다.

```sql
ORDER BY
  CASE WHEN fraud_score IS NULL THEN 1 ELSE 0 END,
  fraud_score ASC
```

즉, 위험도가 높다는 이유로 매물을 검색 결과에서 몰래 제거하지 않는다.

### 8.2 상세 리포트

매물 선택 후 `계약안전` 탭에서 저장된 `fraud_score`를 표시한다. 보증가입 가능성,
신탁등기, 압류·가압류, 체납 증빙 등은 별도 항목이며 이 확률 하나로 대체하지 않는다.

### 8.3 API 단건 재계산

`POST /fraud/score`는 전달받은 매물 필드로 `FraudRiskScorer.score()`를 호출하여 다음을
반환한다.

- `fraud_score`
- `grade`
- `decision_threshold`
- 설명용 `debt_ratio`, `senior_ratio`, `recovery_cushion`
- 사용 모델 경로와 라벨 출처상태

## 9. 확률 피처와 설명용 안전지표의 차이

API가 반환하는 `debt_ratio`, `senior_ratio`, `recovery_cushion`은 HF 확률모형의
부채비율과 별도의 **경매회수 설명지표**다.

```text
예상 경매회수액 = 주택시세 × 0.75

설명용 debt_ratio
= (내 보증금 + 선순위보증금 + 선순위근저당) / 예상 경매회수액

senior_ratio
= (선순위보증금 + 선순위근저당) / 예상 경매회수액

recovery_cushion
= max(예상 경매회수액 - 선순위보증금 - 선순위근저당, 0) / 내 보증금
```

따라서 다음을 구분해야 한다.

| 값 | 용도 | 경매회수율 75% 반영 |
|---|---|---:|
| HF 부채비율 구간 | `fraud_score` 확률 계산 | 아니요 |
| 설명용 `debt_ratio` | 보증금 회수여력 안내 | 예 |
| `senior_ratio` | 선순위 부담 안내 | 예 |
| `recovery_cushion` | 내 보증금 흡수여력 안내 | 예 |

## 10. 모델 선택과 폴백 순서

`FraudRiskScorer`는 메타데이터에 따라 다음 순서로 모델을 고른다.

1. `kind=sklearn_actual_contract_labels`
   - 로컬 계약 단위 실제 라벨로 재학습한 모델과 보정기 사용
2. `kind=published_hf_actual_label_transfer`
   - 현재 활성 경로, HF 공개계수+절편 보정 사용
3. 메타데이터 종류가 없지만 joblib이 존재
   - 과거 합성라벨 모델 호환 경로
4. 모델 산출물이 모두 없음
   - 설명용 부채비율 로지스틱 규칙 사용
   - 이 값은 `emergency_rule/not_calibrated`로 표시하며 보정확률로 주장하지 않음

현재 디렉터리에 과거 `fraud_risk_model.joblib`도 존재하지만, JSON 메타데이터의
`kind`가 공개 HF 이식모형이므로 운영 추론에서는 그 joblib을 사용하지 않는다.

## 11. 실제 계약 라벨 재학습 경로

실제 계약별 HF/HUG 정상·사고 데이터를 확보했을 때 사용할 별도 경로가 이미 구현되어
있지만 현재 활성화되지는 않았다.

### 11.1 입력 방어

`real_labels.py`는 다음 조건을 검사한다.

- provenance의 `data_classification=actual_contract_level`
- `contains_synthetic=false`
- 제공기관과 관찰종료일 존재
- 선택적 SHA-256 일치
- 고유한 계약 ID
- 정상·사고 0/1 두 클래스 존재
- 만기 후 30일이 지나지 않은 미성숙 음성표본 제외
- 파일명이나 행에 `synthetic/합성` 표시가 있으면 중단
- 지역 집계자료는 계약 필수컬럼이 없으므로 중단

### 11.2 시간 분할과 보정

```text
과거 60%             다음 20%                 최신 20%
로지스틱 계수 학습 → 확률보정·임계값 선택 → 최종 성능시험
```

- 결측값: 학습기간 중앙값+결측 지시자
- 표준화: 학습기간 통계만 사용
- 분류기: L2 로지스틱 회귀
- 보정 후보: Platt scaling, isotonic regression
- 선택 기준: 보정기간 후반부 Brier score
- 비용 임계값: 보정기간에서 `20×FN + 1×FP`가 최소인 후보
- 시험지표: ROC-AUC, PR-AUC, Brier, log loss, ECE, precision, recall, confusion matrix

이 경로가 성공하면 메타데이터가 다음처럼 바뀐다.

```json
{
  "kind": "sklearn_actual_contract_labels",
  "label_source_status": "actual_contract_level_verified"
}
```

## 12. 가장 중요한 한계

1. **외부계수 이식**: 현재 모델은 로컬 실제 계약 라벨로 재학습하지 않았다.
2. **모집단 이동**: 수도권 보증가입 계약에서 전국·비보증 합성 매물로 외삽한다.
3. **누락 피처**: 다주택 임대인, 청년 임차인, 실제 전세대출, 가격지수 변화,
   금리차가 현재 매물 DB에서 대부분 0/미상이다.
4. **합성 권리관계**: 현재 10만 매물의 소유자·선순위·가격산정 필드는 실제 등기 확인값이
   아니다.
5. **사전확률 보정**: 평균 4.99%는 현 서비스의 실측 사고율이 아니라 HF 연구율이다.
6. **선택효과**: 보증가입 심사와 금융기관 심사를 통과한 표본의 계수는 일반 임대차의
   인과효과가 아니다.
7. **정적 점수**: DB 구축·재점수화 시점의 값이며 등기·체납·시세가 바뀌면 자동으로
   실시간 갱신되는 구조는 아니다.
8. **법률 판단 아님**: 낮은 점수라도 등기부, 건축물대장, 납세증명, 전입세대,
   보증가입 가능 여부를 반드시 별도 확인해야 한다.

## 14. 재현 명령

현재 HF 공개계수 이식모형을 다시 만들고 전세 매물을 재점수화하려면 다음을 실행한다.

```powershell
python -m src.fraud_risk.bootstrap_published_hf `
  --database data/generated/jeonse_helper.db `
  --false-negative-cost 20 `
  --false-positive-cost 1 `
  --apply
```

검증된 실제 계약 라벨을 확보한 뒤 이식모형을 대체하려면 다음을 실행한다.

```powershell
python -m src.fraud_risk.train_actual `
  --labels data/downloaded/real_estate/hug/actual_contract_labels.csv `
  --provenance data/downloaded/real_estate/hug/actual_contract_labels.provenance.json `
  --false-negative-cost 20 `
  --false-positive-cost 1 `
  --apply
```

## 15. 개선 우선순위

1. 실제 계약 단위·만기 성숙 HF/HUG 라벨 확보
2. 현재 0/미상인 임대인 다주택·임차인·전세대출·가격지수·금리 피처 연결
3. 합성 권리관계 대신 계약 직전 공식 등기·납세·보증심사 데이터 사용
4. 전국·주택유형별 시간 외부검증 및 확률 재보정
5. 월별 드리프트, 관측 사고율, Brier/ECE, 비용 손실 모니터링
6. 위험도 화면에 상위 기여 피처와 누락 피처 상태 표시

현재 모델의 목적은 위험 매물을 확정 판정하는 것이 아니라, 동일한 검색 후보 안에서
추가 확인이 필요한 매물을 먼저 식별하고 사용자에게 계약 전 실사를 유도하는 것이다.
