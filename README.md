## 초록

청년의 주거 선택은 단순한 매물 검색이 아니다. 사용자는 거래유형, 지역, 예산, 통근, 안전, 금융상품 자격, 보증금 미반환 위험, 미래 소득과 생애사건을 동시에 고려해야 한다. 기존 검색 서비스는 보통 조건에 맞는 매물을 나열하고, 금융 서비스는 상품 목록을 별도로 제공하며, 언어모델 기반 상담은 근거가 약하거나 수치 계산을 모델의 자유 생성에 맡기는 문제가 있다. 본 논문은 이 세 영역을 하나의 검증 가능한 의사결정 파이프라인으로 결합한 **KB HouseAgent**를 기술한다.

시스템의 핵심 원칙은 “언어모델이 해석하고, 결정적 코드가 검증·계산하며, 모든 판단을 추적한다”이다. 자연어는 원자적 조건으로 분해되고, 관계형 데이터베이스 질의로 변환되며, 생성된 SQL은 허용 테이블·열·함수, 읽기 전용 연결, 행 수 제한, 실행시간 제한으로 방어된다. 매물·금융상품 후보는 사용자 초기조건의 교집합에서만 확장된다. 경로 API는 SQL 및 공간 사전필터 이후 최대 5개 후보에만 적용한다. 상세 판단에서는 보증사고 로짓모형, 집주인 총자산 대비 보증금 비율 추정, 다가구 선순위보증금 시나리오, 전세가율 확률분포를 서로 합산하지 않고 독립적으로 제시한다.

장기 결과는 고정 상승률 한 줄이 아니라 월 단위 10,000개 몬테카를로 경로로 계산한다. 소득·물가·금융자산수익률·주택가격 충격의 상관을 반영하고, 실직·출산·상속·금리 2%p 상승을 시나리오화한다. 후보 선택은 자산 성장, 월 부담, 안전, 통근, 유동성, 부채를 동시에 다루는 파레토 분석과 혼합정수계획 형태로 기술된다. 집값 전망은 국토교통부 실거래가 월별 패널에서 계절 기준선, Ridge, 히스토그램 기반 그래디언트 부스팅, LightGBM을 walk-forward 방식으로 비교하고, conformal 보정으로 80%·95% 예측구간을 만든다.

2026-07-30 활성 프로토타입은 수원시 팔달구 948개 매물, 금융상품 83개, 실거래 상세 284,052건, 가격 관측 931,929건, R-ONE 관측 88,541건을 포함한다. 현 집값모형은 387개 walk-forward 검증 표본에서 LightGBM이 월 로그수익률 MAE 0.03044, 방향정확도 0.6227을 보였고, conformal 보정 후 구간 포함률은 80.36%와 95.35%였다. 다만 활성 매물은 실시간 중개 플랫폼 재고가 아니며, 집주인 실제 총자산과 건물별 실제 선순위보증금 라벨은 없다. 따라서 본 시스템은 계약·대출·법률 판정을 대신하는 자동 의사결정기가 아니라, 불확실성과 근거를 함께 보여주는 연구용 의사결정 지원 시스템이다.

**주요어:** 청년 주거, 에이전틱 RAG, Text-to-SQL, 전세보증 사고, 몬테카를로 시뮬레이션, 다목적 최적화, conformal prediction, 의사결정 감사

## Abstract

Housing decisions for young adults require the joint consideration of property
prices, transaction types, commuting constraints, financial-product
eligibility, deposit-return risk, liquidity, and uncertain lifetime income.
Existing systems commonly expose these components as disconnected search or
catalog interfaces, while unconstrained language-model advisors can generate
unsupported numbers and recommendations. This paper presents **KB HouseAgent**,
a provenance-aware decision-support system that separates language
understanding from deterministic retrieval, validation, risk modeling,
simulation, and optimization.

Natural-language requests are decomposed into atomic constraints and translated
into guarded relational queries. Generated SQL is restricted to read-only
`SELECT` statements, allowlisted schemas and functions, bounded execution, and
parameter binding. Expensive routing calls are performed only after relational
and spatial prefiltering and are capped at five candidates per search. The
system reports guarantee-incident probability, estimated owner-asset exposure,
senior-tenant deposits, and probabilistic jeonse ratios as distinct quantities
rather than collapsing them into a single risk score. Long-horizon outcomes
are evaluated with 10,000 monthly Monte Carlo paths including correlated
income, inflation, liquid-asset, and house-price shocks, along with
unemployment, childbirth, inheritance, and a 2-percentage-point interest-rate
stress. Property-finance-loan combinations are represented through Pareto
analysis and a mixed-integer optimization interface. House-price forecasts are
selected by expanding-window walk-forward validation and calibrated with
conformalized quantile regression.

The active 2026-07-30 prototype contains 948 properties in Paldal-gu, Suwon,
83 finance programs, 931,929 price observations, 284,052 detailed RTMS
transactions, and 88,541 R-ONE observations. The selected LightGBM forecasting
model achieved a monthly log-return MAE of 0.03044 and directional accuracy of
0.6227 on 387 walk-forward observations; calibrated 80% and 95% intervals
attained empirical coverages of 0.8036 and 0.9535. A full offline regression
suite passed 212 tests. We explicitly identify limitations: the active
inventory is not a live brokerage feed, property coordinates are analytical
representative points, owner assets are population-level estimates, and
building-level legal senior deposits lack verified labels. Accordingly, KB
HouseAgent is a reproducible research prototype for evidence-grounded decision
support, not an automated lender, appraiser, guarantor, or legal authority.

# 1. 서론

## 1.1 문제 배경

주거 선택은 다음 하위 문제의 결합이다.

1. **자연어 선호 이해:** “아주대 근처”, “대출을 받아서라도 가장 좋은 집”, “전세가 좋을까 월세가 좋을까”처럼 불완전한 목표를 구조화한다.
2. **시장 후보 검색:** 거래유형·가격·면적·주택유형·지역·통근 등 이질적인 조건의 교집합을 구한다.
3. **금융상품 자격 판정:** 나이, 혼인, 자녀, 소득, 자산, 지역, 거래유형, 주택가격 등 동적 조건을 확인한다.
4. **계약 위험 분석:** 보증금 미반환, 임대인 자산 대비 노출, 선순위 임차보증금, 보증가입 가능성은 서로 다른 위험축이다.
5. **장기 자산 분석:** 주택가격뿐 아니라 현금흐름, 대출상환, 생활비, 통근비, 실직과 출산을 함께 계산한다.
6. **설명과 책임성:** 어떤 데이터, SQL, 모델버전, 가정이 결론을 만들었는지 재현할 수 있어야 한다.

이들을 하나의 언어모델에 자유 형식으로 질문하면 수치 오류와 근거 없는 단정이 생긴다. 반대로 모든 입력을 고정 폼으로만 받으면 자연어의 유연성이 사라진다. 본 연구는 언어모델을 **제어면(control plane)**, 데이터베이스·통계모형·시뮬레이터를 **계산면(data plane)**으로 분리한다.

## 1.2 연구 질문

본 시스템은 다음 질문을 다룬다.

- **RQ1.** 불완전한 자연어 주거 목표를 검증 가능한 관계형 조건으로 변환할 수 있는가?
- **RQ2.** 언어모델의 유연성을 유지하면서 잘못된 SQL, 임의 수치, 과도한 외부 API 호출을 차단할 수 있는가?
- **RQ3.** 전세 위험을 단일 점수로 뭉개지 않고 서로 다른 관측·추정량과 불확실성으로 분리할 수 있는가?
- **RQ4.** 매물과 금융상품 선택을 장기 생애자산의 확률분포 및 다목적 최적화 문제로 표현할 수 있는가?
- **RQ5.** 사용자에게 제시된 모든 판단을 데이터·모델·SQL·가정 수준에서 재생할 수 있는가?

## 1.3 기여

본 연구의 기술적 기여는 다음과 같다.

1. **검증형 RDB-RAG:** 벡터 유사도 검색 대신 스키마 인지 Text-to-SQL과 파라미터 질의를 결합하고, 생성 SQL에 다층 안전장치를 적용한다.
2. **승인 기반 조건 편집:** 모호한 입력은 질문으로 해소하고, 조건 변경은 UI의 명시적 승인 버튼을 거쳐야 한다.
3. **위험축 분리:** 보증사고 추정확률, 집주인 총자산 대비 노출, 선순위보증금, 전세가율 스트레스를 별개 결과로 유지한다.
4. **확률적 생애자산 엔진:** 10,000개 월별 경로, 상관 충격, 금리 스트레스, 실직·출산 이벤트로 순자산 분포와 현금고갈 가능성을 계산한다.
5. **파레토·최적화 추천:** 단일 휴리스틱 순위 대신 자산, 부담, 안전, 통근, 유동성, 부채의 상충을 명시한다.
6. **불확실성 보정 집값 전망:** walk-forward 백테스트와 conformal prediction으로 점 예측보다 구간을 우선한다.
7. **원자 작업 DAG 스케줄링:** FIFO, HEFT, branch-and-bound, CP-SAT, 제한적 treewidth DP를 공통 IR 위에서 비교하고 포트폴리오로 선택한다.
8. **의사결정 감사:** `decision_run_id` 아래 입력, SQL, 파라미터, 데이터·모델 버전, fallback, 결과 해시를 저장한다.

# 2. 문제 정의

## 2.1 사용자·매물·상품

사용자 프로필을

$$
u=(a,m,c,y,i,A,G,J,L,\theta)
$$

로 둔다. 여기서 $a$는 나이, $m$은 혼인상태, $c$는 자녀 및 출산계획, $y$는 소득, $i$는 직장·학교, $A$는 보유자산, $G$는 예정 증여·상속, $J$는 직업상태, $L$은 생활비 벡터, $\theta$는 선호가중치다.

매물 $p$는 거래가격·보증금·월세·면적·주택유형·위치·건물특성·위험특성으로, 금융상품 $f$는 대상·지역·금리·한도·기간·상환방식·자격규칙으로 표현한다.

후보 조합은

$$
x=(p,f,\ell)
$$

이며 $\ell$은 실제 적용 대출금액이다. 상품을 선택하지 않는 경우 $f=\varnothing$, $\ell=0$이다.

## 2.2 초기조건과 추가조건의 집합 의미

초기 화면 조건을 $C_0=\{c_1,\dots,c_k\}$라 하면 최초 우주는

$$
U_0=\bigcap_{j=1}^{k}\{p:c_j(p)=1\}
$$

이다. 빈 입력은 `아무거나`라는 가짜 조건을 만들지 않고 해당 $c_j$ 자체를 생략한다. 대화에서 승인된 추가조건 $A_t$는 항상 이전 우주의 부분집합을 만든다.

$$
U_t=U_{t-1}\cap\{p:A_t(p)=1\}
$$

즉 에이전트는 사용자가 승인하지 않은 조건으로 검색 우주를 넓히지 않는다. “다른 동네도 찾아줘”처럼 명시적 범위 확장 의도는 별도 추천 경로로 처리한다.

## 2.3 의사결정 목적

후보 $x$의 목적벡터를

$$
\mathbf{z}(x)=
\left[
W_T(x),\;
-B_M(x),\;
S(x),\;
C(x),\;
Q(x),\;
-D(x)
\right]
$$

로 둔다.

- $W_T$: 시점 $T$의 순자산
- $B_M$: 월 주거부담
- $S$: 안전 효용
- $C$: 통근 효용
- $Q$: 유동성
- $D$: 부채

목적들은 충돌한다. 따라서 “가장 좋은 집”은 절대적 정의가 아니라 사용자 가중치 $\theta$와 제약을 만족하는 파레토 후보 중 하나다.

## 3.2 요청 생명주기

1. UI가 사용자 프로필과 초기조건을 저장한다.
2. 자연어가 들어오면 Planner가 의도와 슬롯을 JSON으로 만든다.
3. 모호성이 의사결정 결과를 바꾸면 질문을 반환한다.
4. 조건 편집 의도는 `pending condition`을 만들고 UI 승인을 기다린다.
5. 추천·상담 의도는 승인 없이 기존 우주에서 도구를 실행한다.
6. Text-to-SQL 또는 안전한 파라미터 질의가 DB 후보를 검색한다.
7. 경로·안전·편의·금융·위험 모델이 필요한 후보만 보강한다.
8. 시뮬레이션·최적화가 정량 결과를 만든다.
9. LLM은 제공된 근거만 요약하며 계산값을 새로 만들지 않는다.
10. 전체 단계는 `decision_run_id`로 감사 테이블에 기록된다.

# 4. 자연어 에이전트와 관계형 RAG

## 4.1 왜 벡터 RAG가 아닌가

본 서비스의 핵심 사실은 “금리 2% 미만”, “보증금 8천만 원 이하”, “수원시 팔달구”, “월세”처럼 정확한 비교·교집합이다. 문서 임베딩의 의미 유사도보다 관계형 조건이 적합하다. 따라서 본 논문에서 RAG는 **RDB-grounded retrieval-augmented generation**을 뜻한다.

정책 설명의 비정형 문장은 DB의 설명 열에 저장할 수 있지만, 자격·가격·지역 필터는 SQL로 수행한다. 이 설계는 원래의 RAG 개념이 외부 지식을 생성에 결합한다는 점을 계승하되, 검색기를 밀집 벡터가 아닌 관계형 질의로 특화한다.

## 4.2 Planner

Planner의 출력은 자유 문장이 아니라 JSON Schema를 따르는 계획이다.

```json
{
  "intent": "goal_best_affordable",
  "action": "proceed",
  "slots": {
    "region": "수원시",
    "include_finance": true
  },
  "qa_args": {},
  "tool_calls": [],
  "reason": "대출 포함 예산 내 최적 매물 요청"
}
```

대표 의도는 다음과 같다.

| 의도 | 의미 |
|---|---|
| `recommend` | 조건에 맞는 일반 매물 추천 |
| `qa_finance` | 금융상품 질의 |
| `goal_financed_jeonse` | 금융상품을 결합한 전세 목표 |
| `qa_lease_compare` | 전세·월세 장기 비교 |
| `goal_best_affordable` | 대출 포함 예산 내 최적 매물 |
| `qa_market` | 지역 또는 선택 매물의 시장 전망 |
| `qa_buy_or_wait` | 지금 구매와 대기의 비교 |
| `goal_alternative_areas` | 예산에 맞는 대체지역 |
| `qa_contract` | 계약·보증·위험 상담 |

OpenAI Structured Outputs는 단순 JSON mode와 달리 주어진 JSON Schema 준수를 목적으로 한다. 시스템은 이를 계획과 SQL 구조에 활용하지만, 스키마 준수 이후에도 의미 검증을 다시 수행한다. 모델 출력이 형식상 유효하다고 해서 질의가 안전하거나 사용자 의도를 충족하는 것은 아니기 때문이다.

## 4.3 모호성 해소와 승인

“아주대”만 입력하면 다음 상태가 가능하다.

```text
문자열 감지
 → 장소 후보: 아주대학교
 → 목적 불명: 인근 거리인가, 자가용인가, 대중교통인가?
 → 결과를 바꾸는 누락 슬롯 식별
 → 사용자 질문
 → 답변을 pending condition으로 생성
 → 채팅 위 [조건 추가] 버튼
 → 승인 후에만 SQL/UI 필터 반영
```

단순한 “응” 텍스트는 승인으로 해석하지 않는다. 이 방식은 언어모델이 사용자 조건을 조용히 바꾸는 것을 방지한다.

## 4.4 대화 기억

AI 추천/상담 채널에서는 같은 세션의 사용자·도우미 발화를 Planner와 최종 합성 프롬프트에 다시 제공한다. 다만 개인정보 최소화 원칙에 따라 무제한 영구 기억이 아니라 세션 범위의 대화 상태다. 조건편집 채널과 추천채널은 목적이 다르므로 동일한 UI 동작으로 합치지 않는다.

## 4.5 Text-to-SQL

SQL 생성은 스키마, 허용 열, 사용자 조건, 필수 반환열을 입력받는다. 출력은 SQL 문자열과 바인딩 파라미터를 분리한다.

```sql
SELECT program_id, name, rate_pct, max_amount_manwon
FROM finance_programs
WHERE product_kind LIKE ?
  AND rate_pct < ?
  AND (income_limit_manwon IS NULL OR income_limit_manwon >= ?)
ORDER BY rate_pct ASC
LIMIT ?
```

파라미터 예시는 `["%대출%", 2.0, 300, 10]`이다. 값의 문자열 연결을 피하고 SQLite 바인딩을 사용한다.

### SQL 방어층

1. `SELECT`만 허용한다.
2. 주석, 다중 문장, DDL, DML을 거부한다.
3. 테이블·열·함수를 allowlist로 제한한다.
4. 필수 슬롯이 `WHERE`에 반영되었는지 검사한다.
5. 필요한 설명 열이 `SELECT`에 포함되었는지 검사한다.
6. SQLite를 읽기 전용 URI로 연다.
7. `PRAGMA query_only`와 authorizer를 설정한다.
8. progress handler로 장시간 질의를 중단한다.
9. 최대 반환행을 500개로 제한한다.
10. 실패하면 사전 정의된 파라미터 질의로 fallback한다.

이 접근은 문법 제약 디코딩을 사용하는 PICARD와 목적이 유사하지만, 본 구현은 디코딩 시점이 아니라 생성 후 정적·실행 검증으로 안전을 확보한다.

## 4.6 재시도와 fallback

일시 오류 `408, 409, 429, 500, 502, 503, 504`, timeout, connection error는 최대 3회 지수 backoff와 jitter로 재시도한다. 인증·권한 오류는 반복해도 해결되지 않으므로 즉시 실패한다. 주 모델 실패 시 설정된 저비용 fallback 모델을 조건부로 사용한다.

LLM 전체가 불가능한 경우:

- Planner: 규칙 기반 의도·슬롯 추출
- 금융 SQL: 파라미터 질의
- 지도: 캐시 또는 거리·평균속도 추정임을 표시
- 최종 답변: 고정 템플릿이 아니라 검색 결과 기반 결정적 요약

fallback은 숨기지 않고 RAG trace와 감사 단계에 기록한다.

## 4.7 근거 제한 합성

최종 언어모델은 다음 계약을 따른다.

- 제공되지 않은 가격·금리·자격·거리·확률을 만들지 않는다.
- DB 결과가 0건이면 0건이라고 말한다.
- 추정과 관측을 구분한다.
- 상품 “가능”을 확정 승인으로 표현하지 않는다.
- 위험확률을 범죄 발생확률로 바꾸지 않는다.
- 긴 설명은 핵심 결론·근거·주의로 구조화한다.

이는 ReAct의 추론-행동 상호작용을 제품 제약에 맞게 축소한 형태다. 내부 자유 추론을 사용자에게 그대로 노출하는 대신, 실행된 행동과 근거를 구조화된 trace로 공개한다.

## 4.8 제한적 웹 검색 도구

DB·지도·공식 API로 해결할 수 없는 최신 지역정보에는 OpenAI Responses
API의 웹 검색 도구를 선택적으로 사용한다. 웹 결과가 곧바로 필터가
되지는 않는다.

```text
내부 도구 실패 또는 최신 비정형 사실 필요
 → 검색 질의 생성
 → 공식기관·원문 우선 검색
 → 출처 URL과 시점 보존
 → 장소라면 지오코딩 API로 다시 검증
 → 검증 성공 결과만 조건 후보로 변환
 → 사용자 승인
```

웹 문서 안의 지시문은 데이터일 뿐 시스템 명령으로 실행하지 않는다.
검색이 실패하거나 출처가 불분명하면 좌표·가격·자격을 추측하지 않고
사용자에게 정확한 주소나 원문을 요청한다.

# 5. 데이터 체계와 출처

## 5.1 데이터 계보 원칙

모든 데이터는 다음 중 하나로 분류한다.

1. **공식 원천 관측:** 정부·공공기관 API/CSV의 실거래·시설·통계.
2. **사용자 제공 원천:** 사용자가 합법적으로 확보해 프로젝트에 제공한 금융상품 또는 프로토타입 매물 자료.
3. **파생 관측:** 원천을 정규화·지오코딩·집계한 값.
4. **모델 추정:** 관측값에서 예측한 값.
5. **시나리오 가정:** 라벨 부재로 사용자가 해석해야 하는 가정값.
6. **합성 실험:** 분포 보존·다양성 시험을 위해 생성한 비운영 데이터.

`is_synthetic=0`은 합성 생성기가 만든 행이 아니라는 뜻이지, 현재 시점의 실시간 중개 매물임을 보장하지 않는다.

## 5.9 과거 합성·증강 실험

`src/data_augmentation/`에는 현재 팔달구 활성 DB와 별개인 전국형 합성
실험 코드가 남아 있다. `multi-source-conditional-bootstrap-v2` 실험은
20,000개, 208열 매물을 생성했고 다음 원리를 사용했다.

1. 주택유형×거래유형 18개 조합에 목표 건수를 배정한다.
2. 지역·유형·거래 조건부로 실제 RTMS anchor를 복원추출한다.
3. 최신 거래에 반감기 18개월의 지수가중치를 준다.

$$
w_i=\exp\left(-\log 2\cdot
\frac{\operatorname{ageMonths}_i}{18}\right)
$$

4. 면적은 거래원본을 중심으로 작은 log-normal 교란을 준다.
5. 매매 ㎡당 가격은 시간 holdout으로 검증한
   `HistGradientBoostingRegressor`의 조건부 평균에 실제 잔차를 다시
   표본화해 분산 축소를 완화한다.
6. 거래유형별 금액 불변식과 208열 스키마를 결정적 규칙으로 검증한다.
7. 원본 주소·동호·중개사 개인정보를 복제하지 않고 합성 식별자를 쓴다.

당시 가격모형 보고값은 로그 ㎡당 가격 $R^2=0.7552$, MdAPE 17.68%였으나
해당 데이터는 서울 편중이 심했고 현재 운영 매물로 사용되지 않는다.
20,000건·10만건을 과거에 생성했다는 사실은 현재 DB에 그 수가 있다는
뜻이 아니다. GAN/CTGAN을 기본으로 쓰지 않은 이유는 희소 조합 보장,
법률·업무 불변식, CPU 재현성, 원본-합성 계보가 더 중요했기 때문이다.

재현 예:

```powershell
python -m src.data_augmentation.generate --count 20000 --n-users 2000 `
  --price-model hedonic --seed 42
```

생성 후 활성 프로토타입 DB를 덮어쓰지 않도록 별도 출력경로와 브랜치를
사용해야 한다.

# 7. 검색, 공간 및 경로 계산

## 7.1 단계적 후보 축소

전체 948건 또는 향후 전국 자료에 외부 경로 API를 모두 호출하지 않는다.

```text
초기조건 SQL 교집합
 → 가격·유형·지역 SQL
 → 목적지 좌표를 중심으로 bounding box/Haversine 사전필터
 → 저비용 근사 통근순위
 → 최대 5개 후보만 실제 경로 API
 → 정확 경로시간 조건
 → 최종 후보
```

`ROUTE_API_EXACT_CANDIDATE_LIMIT` 기본값은 5, 경로 동시 작업자는 3이다.

## 7.2 좌표 거리

두 WGS84 좌표의 대권 근사거리는 Haversine 식으로 계산한다.

$$
a=\sin^2\frac{\Delta\phi}{2}
+\cos\phi_1\cos\phi_2\sin^2\frac{\Delta\lambda}{2}
$$

$$
d=2R\arcsin\sqrt{a}, \quad R=6371\text{ km}
$$

이는 도로·철도 네트워크 시간을 대신하지 않는다. API 후보 축소와 반경 시설집계에만 쓴다.

## 7.3 장소명 해석

장소 문자열은 정규화, 별칭, 지오코딩 순으로 처리한다.

1. 공백·접미사 정규화
2. 알려진 대학·역·기관 별칭
3. Naver Geocoding
4. 검색어 확장 재시도
5. 후보가 여러 개면 사용자 선택
6. 모두 실패하면 “위치를 찾지 못함”을 명시

비슷한 단어로 재시도하더라도 조용히 다른 장소를 확정하지 않는다.

## 7.4 이동수단 API

- **자가용:** Naver Directions 5. 실시간 교통 기반 자동차 경로, 거리·시간·통행료·연료비 필드를 사용한다. 대중교통이나 도보 API로 오용하지 않는다.

# 8. 금융상품 자격 및 자금조달

## 8.1 자격판정의 세 값

각 자격조건은 이진 참/거짓이 아니라 다음 3값 논리를 사용한다.

$$
e_j(u,f)\in\{\text{pass},\text{fail},\text{unknown}\}
$$

- `pass`: 사용자 값이 있고 조건을 만족.
- `fail`: 사용자 값이 있고 조건을 불만족.
- `unknown`: 필요한 사용자 값 또는 상품 규칙이 없음.

전체 예비자격은 한 조건이라도 fail이면 `불일치`, fail이 없고 unknown이 있으면 `추가확인`, 모두 pass면 `예비충족`이다. `예비충족`도 은행 승인과 동일하지 않다.

미혼 또는 혼인상태 미선택 시 배우자 소득 입력을 비활성화한다. 다자녀 상품은 자녀 조건을 만족하지 않으면 검색 결과에서 제외해야 한다. 입력을 비우면 해당 상품의 정밀 판정이 제한된다는 경고를 제공한다.

## 8.2 자금식

매매의 초기 필요현금은

$$
H_0=P+\tau P-\ell-G
$$

이다. $P$는 매매가, $\tau$는 취득·중개·부대비용률, $\ell$은 대출, $G$는 증여·상속 투입액이다. 임차는

$$
H_0=D+\tau_rD-\ell-G
$$

로 계산한다. 현재 최적화 기본 부대비용률은 매매 1.5%, 임차 0.3%다. 실제 세율·중개보수는 지역·가격·생애최초 여부 등에 따라 달라지므로 정산 전 다시 계산해야 한다.

## 8.3 원리금

원리금균등 월상환액은

$$
M=L\frac{r(1+r)^n}{(1+r)^n-1}
$$

이다. $L$은 대출원금, $r$은 월금리, $n$은 개월 수다. $r=0$이면 $M=L/n$이다.

전세대출 등 만기일시상환은 월 이자

$$
I_m=Lr
$$

와 만기 원금상환을 구분한다. 상품의 실제 상환방식을 모르면 원리금균등으로 임의 확정하지 않고 추가확인 상태로 둔다.

## 8.4 적정 대출금

시스템은 상품 공개한도, 담보·자본비율 한도, 월 상환가능액 한도 중 최소를 제안한다.

$$
L_{\max}=\min(L_{\text{published}},L_{\text{capital}},L_{\text{affordable}})
$$

자동 제안 뒤 사용자가 금액을 조정할 수 있다. 다만 조정값은 다시 월부담·현금보유·상품한도 제약을 통과해야 한다.

# 9. 전세보증 사고 추정모형

## 9.1 예측대상

본 모형의 종속변수는 “범죄로서의 전세사기”가 아니라 **보증기관 표본에서의 전세보증금 미반환 사고 여부**다.

$$
Y=
\begin{cases}
1 & \text{보증사고 관측}\\
0 & \text{사고 미관측}
\end{cases}
$$

공식 연구는 2019~2023년 발급된 수도권 보증계약의 사고를 2024년 12월까지 관찰했다. 총 453,122개 보증 데이터가 분석대상이며 사고는 22,601건이다. 표본은 보증에 가입된 계약이므로 전체 임대차 시장과 선택편향이 다르다.

## 9.2 로지스틱 회귀

p(Y=1\mid x)=\sigma(\eta)

$$

이다. 이 20:1은 사회적 비용 연구로 추정된 값이 아니라 보수적 제품정책이다. 따라서 별도 민감도 분석이 필요하다.

1. 시간순 60/20/20 train/calibration/test 분할.

# 10. 임대인 총자산 대비 보증금 노출 추정

## 10.1 왜 직접 관측할 수 없는가

특정 집주인의 전재산은 실거래가·건축물대장·가계금융복지조사 어느 하나에도 직접 나타나지 않는다. 이 시스템은 다음 세 확률변수를 결합한다.

- $V_b$: 대상 건물의 시장가치
- $K_o$: 임대인이 소유한 다른 부동산·금융자산의 모집단 배수
- $D_{\text{all}}$: 해당 건물을 포함한 임대인의 보증금 부채

총자산 근사는

$$
A_o=V_b(1+K_o)+A_{\text{financial}}-L_o
$$

처럼 구성할 수 있으나, 실제 구현에서는 가계금융복지조사 임대주택 보유가구의 가중 bootstrap으로 결합 prior를 샘플한다. 결과는 특정 임대인의 조회값이 아니라 조건부 모집단 추정이다.

## 10.3 하위 모형

### 가구·호수 모형

건축속성 $x_b$에서 임대가능 단위 수 $N_b$를 예측한다. Poisson, negative binomial, HistGradientBoosting Poisson, LightGBM Poisson 후보를 비교한다.

Poisson 평균은

$$
\mathbb{E}[N_b\mid x_b]=\exp(f(x_b))
$$

로 양수를 보장한다. 실제 과산포가 크면 negative binomial이 이론상 유리하고, 비선형 상호작용은 tree boosting이 다룬다.

### 호당 보증금 분포

보증금 $D_i$의 조건부 분위수

$$
\hat q_\tau(x_i),\qquad
\tau\in\{0.1,0.25,0.5,0.75,0.9\}
$$

를 학습한다. quantile loss는

$$
\rho_\tau(u)=u(\tau-\mathbf{1}[u<0])
$$

이다. 예측 분위수가 교차하면 단조 정렬하고, 분위수 사이를 piecewise-linear inverse CDF로 샘플한다.

### 건물가치

매매 실거래와 건축속성에서 건물 가치 분위수를 예측한다. 표본이 적기 때문에 복잡한 모델의 숫자를 확정 시세로 보여주지 않고 넓은 구간을 유지한다.

# 11. 다가구 선순위 임차보증금 추론

## 11.1 법률값과 모델값의 구분

선순위 임차보증금 총합은 전입·점유·확정일자·소액임차인 요건·근저당 순위 등 법률사실에 의존한다. 공개 실거래와 건축물대장만으로는 특정 건물의 실제 순위를 알 수 없다. 따라서 모델 출력은 계약서·전입세대확인·확정일자 현황·등기부 확인 전의 **시나리오 추정**이다.

## 11.2 생성모형

대상 호실을 제외한 임대가능 단위 수를 $N_{-s}$라 한다. 등록 단위 수가 있으면 관측값을 사용하고, 없으면 단위 수 모형을 사용한다.

점유율:

$$
\pi\sim\operatorname{Beta}(\alpha,\beta)
$$

$$
N_{\text{occ}}\mid \pi\sim\operatorname{Binomial}(N_{-s},\pi)
$$

이를 적분하면 Beta-Binomial 혼합이 되어 점유율 불확실성과 호수 불확실성을 함께 반영한다.

다른 임차인 $i$의 보증금은 조건부 분위수 inverse CDF에서 뽑는다.

$$
D_i=F^{-1}(U_i\mid x_b,x_i)
$$

같은 건물 호실의 보증금이 독립이라는 가정을 완화하기 위해 공유 로그 랜덤효과 $Z_b$를 둔다.

$$
\tilde D_i=D_i\exp(Z_b),\qquad
Z_b\sim N(-\sigma_b^2/2,\sigma_b^2)
$$

기본 $\sigma_b=0.12$, 민감도는 0, 0.12, 0.25다. 평균을 보존하도록 정규분포 평균을 $-\sigma_b^2/2$로 이동한다.

선순위 indicator:

$$
S_i\sim\operatorname{Bernoulli}(p_s)
$$

실제 순위 라벨이 없으므로 기본 $p_s=0.9$인 시나리오 prior를 사용하며 보수모드는 $p_s=1$이다.

최종 선순위보증금:

$$
D_{\text{senior}}=\sum_{i=1}^{N_{\text{occ}}}S_i\tilde D_i
$$

## 11.3 보정과 평가

호당 보증금 모델은 LightGBM quantile이며 $\tau=0.05,0.1,0.25,0.5,0.75,0.9,0.95$를 학습한다. validation에서 quantile crossing은 42.46%에서 단조보정 후 0%가 되었다. 로그공간 conformal correction으로 50%, 80%, 90% 구간을 보정했다.

테스트 결과:

| 지표 | 값 |
|---|---:|
| 테스트 행 | 11,100 |
| 중앙절대오차 | 355.58만원 |
| 중앙 APE | 28.48% |
| 50% 구간 포함률 | 49.06% |
| 80% 구간 포함률 | 78.21% |
| 90% 구간 포함률 | 88.26% |

그러나 점유, 선순위, 건물별 선순위 총합 실제라벨은 모두 0건이다. 따라서 최종 선순위보증금 자체는 평가되지 않았고 `model_mode=scenario_only`다. 호당 보증금 예측이 평가되었다고 해서 법률상 선순위 총합이 검증된 것은 아니다.

## 11.4 출력 원칙

- P5/P10/P50/P90/P95를 제공한다.
- 보수모드와 공유효과 민감도를 나란히 보여준다.
- 선택 사용자의 보증금은 “기존 선순위”에 포함하지 않는다.

# 12. 다가구 전세가율 확률분포

## 12.1 네 개의 비율

각 비율은 의미가 다르다.

1. 전체 보증금 비율

$$
R_{\text{all}}=\frac{D_{\text{all}}}{V_b}
$$

2. 기존 선순위 비율

$$
R_{\text{senior}}=\frac{D_{\text{senior}}}{V_b}
$$

3. 선택 계약 후 비율

$$
R_{\text{post}}=\frac{D_{\text{senior}}+D_s}{V_b}
$$

4. 보수적 선택 계약 후 비율

$$
R_{\text{post}}^{U}
=\frac{D_{\text{senior}}^{U}+D_s}{V_b}
$$

근저당은 이 비율 분자에 섞지 않고 별도 권리부담으로 표시한다. 비율이 100%를 넘더라도 자르지 않는다. 100% 초과 자체가 중요한 위험신호다.

## 12.2 주변확률분포 복원

하위 모델이 원시 표본이 아니라 분위수만 반환할 때 piecewise inverse CDF로 표본을 복원한다. 보증금과 건물가치가 독립이라는 가정을 피하기 위해 Gaussian copula를 사용한다.

$$
\begin{bmatrix}Z_D\\Z_V\end{bmatrix}
\sim N\left(
\begin{bmatrix}0\\0\end{bmatrix},
\begin{bmatrix}1&\rho\\\rho&1\end{bmatrix}
\right)
$$

$$
U_D=\Phi(Z_D),\quad U_V=\Phi(Z_V)
$$

$$
D=F_D^{-1}(U_D),\quad V=F_V^{-1}(U_V)
$$

$\rho\in\{0,0.2,0.4,0.6\}$를 민감도 분석한다. 실제 짝지어진 잔차에서 상관을 학습한 것이 아니므로 이 값들은 시나리오다.

## 12.3 주택가격 스트레스

가격 하락률 $h\in\{0.05,0.10,0.20,0.30\}$에 대해

$$
R^{(h)}=\frac{D}{V(1-h)}
$$

를 계산한다. 기본 표본 수는 20,000이며 1,000~100,000 범위를 허용한다.

UI 해석 기준은 60% 미만 안전, 60~70% 주의, 70~80% 경계, 80% 이상 위험으로 표현할 수 있으나, 이는 법적 보증가입 심사선이나 손실확률과 동일하지 않은 제품 해석구간이다.

# 13. 주택가격 시계열 전망과 뉴스

## 13.1 목표

예측대상은 개별 호가의 정확한 가격이 아니라 지역·주택유형별 향후 3개월 평균 월 로그수익률이다.

$$
y_t=\frac{\log P_{t+3}-\log P_t}{3}
$$

$P_t$는 지역·유형별 ㎡당 월 중앙 실거래가다.

## 13.2 패널 구성

아파트·오피스텔·단독/다가구 매매 RTMS를 법정동 상위 지역코드와 월로 집계한다.

1. 거래금액/전용면적으로 ㎡당 가격 계산.
2. 지역·주택유형·월 중앙값.
3. 달력 인덱스로 재색인.
4. 관측 없는 월은 임의 선형보간하지 않음.
5. 관측 월에 한해 trailing 3개월 중앙값으로 잡음 완화.
6. 극단 월수익률은 [-0.1, 0.1]로 제한.

특징:

$$
x_t=[
r_{t-1},r_{t-3},r_{t-6},
\sigma_{3,t},
\log(1+n_t),
r^{nat}_{t-1},
\sin(2\pi m/12),
\cos(2\pi m/12),
g]
$$

$g$는 지역·주택유형 코드다.

## 13.3 후보모형과 walk-forward

시간 $t$까지 학습해 $t+1$ 이후를 예측하는 확장창 walk-forward를 사용한다. 비교모형:

1. 계절 naive
2. Ridge
3. HistGradientBoosting
4. LightGBM
5. TFT는 데이터 충분성 조건 미달로 제외

현재 supervised row는 1,131, 관측 이력은 36개월 미만이므로 다수 파라미터를 가진 Temporal Fusion Transformer가 안정적으로 우월하다고 보기 어렵다. 복잡한 모델을 기술적 장식으로 쓰지 않고 백테스트 성능으로 선택한다.

## 13.4 결과

검증월은 2025-11~2026-04, 검증표본 387개다.

| 모형 | MAE | 방향정확도 |
|---|---:|---:|
| 계절 naive | 0.05909 | 0.2429 |
| Ridge | 0.03143 | 0.6021 |
| HistGradientBoosting | 0.03082 | 0.6227 |
| LightGBM | **0.03044** | **0.6227** |

선택모형은 LightGBM이다. MAPE도 계산되지만 수익률의 분모가 0에 가까울 수 있어 해석이 불안정하다. 따라서 주 지표는 MAE와 방향정확도다.

## 13.5 conformal prediction

하한·상한 quantile 모델의 원 구간에 calibration residual을 더한다. CQR의 conformity score는

$$
s_i=\max\{\hat q_L(x_i)-y_i,\;y_i-\hat q_U(x_i)\}
$$

이고, 유한표본 분위수 $\hat Q_{1-\alpha}$를 구해

$$
C_\alpha(x)=
[\hat q_L(x)-\hat Q_{1-\alpha},
\hat q_U(x)+\hat Q_{1-\alpha}]
$$

로 보정한다.

| 항목 | 값 |
|---|---:|
| 80% 보정량 | 0.014925 |
| 95% 보정량 | 0.045012 |
| 원 구간 포함률 | 58.66% |
| 보정 80% 포함률 | 80.36% |
| 보정 95% 포함률 | 95.35% |

이는 사용한 검증분포에서의 주변적 포함률이다. 개별 지역별 조건부 포함률을 보장하지 않는다.

## 13.6 뉴스의 역할

현재 뉴스는 숫자 예측을 직접 이동시키는 외생변수가 아니다. 역사적 시점별 뉴스 수집·시차·중복제거·사후수익률 라벨로 학습한 검증셋이 없기 때문이다.

뉴스 파이프라인은:

1. 지역과 주택시장 관련 기사 검색.
2. 중복·무관 기사 제거.
3. LLM이 가격 영향 방향, 근거, 불확실성을 분류.
4. 긍정·중립·부정 비율과 핵심 기사만 표시.
5. 정량 시계열 전망과 별도 카드로 제공.

뉴스 판단에서 LLM이 실패하면 제한적 키워드 fallback을 명시하고, 마치 정교한 감성모형처럼 표현하지 않는다.

# 14. 확률적 생애자산 시뮬레이션

## 14.1 상태와 시간

월 $t$의 상태는

$$
s_t=(C_t,H_t,D_t,B_t,Y_t,E_t)
$$

이다.

- $C_t$: 현금·금융자산
- $H_t$: 주택가치 또는 임차보증금
- $D_t$: 대출잔액
- $B_t$: 월 생활·주거비
- $Y_t$: 소득
- $E_t$: 고용·가족 이벤트

기본은 10년, 월 단위, 10,000개 경로다. 허용 경로 수는 500~20,000이다. 난수 seed를 감사로그에 저장한다.

## 14.2 상관 충격

소득, 물가, 금융자산수익률, 주택가격의 표준정규 충격을

$$
\epsilon_t\sim N(0,\Sigma)
$$

로 둔다.

$$
\Sigma=
\begin{bmatrix}
1&0.22&0.18&0.12\\
0.22&1&-0.08&0.05\\
0.18&-0.08&1&0.28\\
0.12&0.05&0.28&1
\end{bmatrix}
$$

이는 개인별 실증 추정행렬이 아니라 현재 제품 가정이다. 논문 결과를 정책에 사용할 때는 한국 거시·가계 패널로 다시 추정해야 한다.

연간 평균률 $g$를 월 로그평균으로 바꾸면

$$
\mu_m=\frac{\log(1+g)}{12}
$$

이다. 연 변동성은 $\sigma_m=\sigma_y/\sqrt{12}$로 변환한다.

주택가격 연 변동성은 전망의 P10~P90 폭에서

$$
\sigma_H\approx
\frac{q_{0.9}-q_{0.1}}{2\Phi^{-1}(0.9)}
=\frac{q_{0.9}-q_{0.1}}{2\times1.28155}
$$

로 추정하고 [0.03, 0.25]로 제한한다.

## 14.3 현금흐름

월 금융자산:

$$
C_{t+1}=
C_t(1+r^C_t)
+Y_t
-L_t
-R_t
-M_t
-X_t
$$

- $L_t$: 생활비
- $R_t$: 월세·관리비·보유비
- $M_t$: 대출상환
- $X_t$: 자녀·교통·보험·구독·여가 등 추가비용

주택가치:

$$
H_{t+1}=H_t\exp(\mu_H+\sigma_H\epsilon^H_t)
$$

부채는 상환방식에 따라 원리금균등 또는 이자만 상환한다. 전세 만기에는 보증금 반환을 가정해 부채를 상환하지만, 보증금 미반환 위험을 결합한 별도 스트레스 실험이 필요하다.

## 14.4 생활비 입력

UI는 다음을 월 단위로 정규화한다.

- 직장·학교 및 자주 방문하는 곳
- 자동차: 연료, 보험, 정비, 주차
- 대중교통: 버스·지하철/택시 비율, 추가 장거리비용
- 기타 보험료
- 일평균 식비 × 월일수
- 구독서비스 검색 콤보와 사용자 추가
- 통신·인터넷
- 여가

통근지는 입력된 경우 경로 도구에서 자동 계산하고, 없으면 주소를 질문한다.

## 14.5 생애사건

### 실직

연 확률 기본값 5%, 실직 중 소득비율 20%, 기간 3~9개월을 샘플한다. 이는 사용자·직종별 위험을 학습한 값이 아니므로 민감도 변수다.

### 자녀

각 자녀의 출생연도를 별도로 입력한다. 연령별 비용곡선 $c(a)$를 적용해 성장기 증가, 20대 초·중반 정점, 이후 급감을 표현한다.

$$
X^{child}_t=\sum_k c(a_{k,t})
$$

곡선은 법정·필연 비용이 아니라 사용자가 조정할 수 있는 계획 가정이어야 한다.

### 증여·상속

예정 시점과 금액을 일회성 현금유입으로 넣는다. 불확실한 상속을 확정자산처럼 초기 자금조달에 쓰지 않도록 확실성 수준을 구분해야 한다.

## 14.6 위험지표

### 현금고갈

$$
P_{\text{deplete}}
=\Pr\left(\min_{t\le T}C_t<0\right)
$$

### 상환곤란

상환액이 부채상환 전 가처분소득을 3개월 연속 초과하면 distress로 표시한다.

### 순자산

$$
NW_t=C_t+H_t-D_t
$$

P2.5/P10/P50/P90/P97.5를 시점별로 반환해 부채꼴 그래프로 그린다.

### 하방 CVaR

최종 순자산 변화 $\Delta NW_T$의 하위 5% 평균:

$$
\operatorname{CVaR}_{5\%}
=\mathbb{E}[\Delta NW_T\mid
\Delta NW_T\le q_{0.05}]
$$

본 시스템의 “CVaR5”는 손실을 양수로 재정의한 전통적 표기와 부호가 다를 수 있으므로 UI에서 “최악 5% 시나리오 평균 순자산 변화”라고 풀어쓴다.

## 14.7 금리 스트레스

같은 난수 seed로 기본과 대출금리 +2%p 경로를 생성한다. 공통난수(common random numbers)를 사용하면 두 정책 간 차이의 몬테카를로 잡음이 줄어든다.

## 14.8 LLM의 역할

시뮬레이션 숫자는 NumPy 기반 결정적 코드가 계산한다. LLM은 숫자를 생성하지 않고 P10/P50/P90, 고갈확률, 금리민감도, 주요 비용을 설명한다. LLM이 실패해도 그래프와 지표는 생성 가능하다.

# 15. 부동산 × 금융상품 × 대출금액 최적화

## 15.1 후보 생성

최대 60개 매물, 매물당 최대 8개 예비적격 금융상품을 조합한다. 대출금액은 최소·중간·최대·사용자 지정 값을 500만원 단위로 이산화한다.

## 15.2 제약

후보 $x$가 실행 가능하려면:

$$
\text{initial cash}(x)\le A+G
$$

$$
\text{monthly payment}(x)
\le0.35\times\text{monthly disposable income}
$$

$$
\text{remaining liquid cash}
\ge6\times\text{monthly living cost}
$$

그리고 금융상품 예비자격, 공개한도, 거래유형 호환을 만족해야 한다. 위험도는 필터가 아니라 정렬·목적함수다.

## 15.3 정규화와 사용자 성향

각 지표를 후보집합의 [0,1]로 정규화하고 사용자 가중합을 계산한다.

$$
U_\theta(x)=\sum_jw_jz_j(x),\qquad
w_j\ge0,\;\sum_jw_j=1
$$

프리셋 예:

- 자산성장형: 최종 순자산 가중치가 큼
- 월부담 최소형: 월 부담 가중치가 큼
- 안전 우선형: 위험 역수 가중치가 큼
- 통근 우선형: 통근 효용 가중치가 큼

사용자 프로필의 선호가 있으면 이를 가중치에 반영한다. 명시적 선호가 없으면 결과를 한 개로 숨기지 않고 대표 파레토 후보를 함께 보여준다.

## 15.4 파레토 지배

$x$가 $y$를 지배한다는 것은 모든 목적에서 열등하지 않고 하나 이상에서 우월함을 뜻한다.

$$
x\succ y
\iff
\left(\forall j,\;z_j(x)\ge z_j(y)\right)
\land
\left(\exists k,\;z_k(x)>z_k(y)\right)
$$

비지배 후보만 남겨 상충관계를 설명한다.

## 15.5 MILP

후보선택 이진변수 $q_i\in\{0,1\}$:

$$
\max\sum_iU_\theta(x_i)q_i
$$

$$
\sum_iq_i=1
$$

후보 생성 단계에서 제약을 통과한 조합만 남기거나, 추가 선형제약을 MILP에 직접 넣을 수 있다. SciPy `milp`/HiGHS를 사용한다.

현재처럼 “이미 실행 가능한 후보 중 정확히 하나”만 고르는 선형 문제는 사실상 `argmax`로 충분하다. MILP는 공동구매, 복수주택, 기간별 자금배분, 상품조합 같은 향후 확장을 위한 형식적 기반이지 현재 성능을 마법처럼 높이는 요소가 아니다. solver가 없으면 안전하게 argmax로 fallback한다.

# 16. 원자 작업 DAG와 스케줄링

## 16.1 원자화

사용자 조건과 도구 실행을 `TaskNode`로 컴파일한다.

| 필드 | 의미 |
|---|---|
| `id` | 작업 식별자 |
| `duration_ms` | 예측 실행시간 |
| `resource` | SQLite, OpenAI, TMAP, Naver 등 |
| `dependencies` | 선행작업 |
| `demand` | 자원 용량 |
| `expected_tokens` | LLM token 추정 |
| `monetary_cost` | 외부 비용 |
| `candidate_reduction` | 후보 축소 기대효과 |
| `user_importance` | 사용자 중요도 |

비싼 작업 전에 후보를 크게 줄이는 SQL을 배치하는 것이 핵심이다.

## 16.2 알고리즘

### Topological FIFO

결정적 기준선이다. 빠르고 항상 실행 가능한 계획을 제공하지만 critical path와 후보축소 가치를 무시할 수 있다.

### Cost-aware HEFT

HEFT의 upward rank에 후보축소, 중요도, token, 외부비용을 결합한 list scheduling이다. 이론적으로 최적을 보장하지 않지만 매우 빠른 좋은 upper bound다.

### Anytime Branch-and-Bound

HEFT를 초기 upper bound로 사용하고 critical path·자원 작업량 lower bound로 가지치기한다. 작은 DAG에서 최적성을 증명하고, 크기·시간 제한이면 현재 최선계획을 반환한다.

### CP-SAT

작업 start/end 및 interval, 선후관계, 자원별 cumulative capacity, makespan 최소화를 OR-Tools CP-SAT으로 표현한다. HEFT를 solution hint로 넣는다.

### Treewidth-guided DP

무향화 dependency graph의 deterministic min-fill treewidth를 추정한다. 현재 정확 DP는 단일용량·비선점·지원 구조에만 적용한다. 일반 RCPSP 전체에 대한 FPT 해법이라고 주장하지 않으며, 조건을 벗어나면 HEFT로 fallback한다.

### Portfolio

동일 deadline 안에서 알고리즘을 경쟁시키고, 검증을 통과한 결과 중 makespan이 최소인 계획을 선택한다. 동률이면 planning latency가 짧은 것을 택한다.

## 16.3 오프라인 벤치마크

외부 API를 호출하지 않고 고정 duration으로 7개 DAG를 비교했다.

| 알고리즘 | 유효/전체 | 평균 계획시간 | 기준 makespan 평균차이 |
|---|---:|---:|---:|
| FIFO | 7/7 | 0.226 ms | 4.3945% |
| Cost-aware HEFT | 7/7 | 0.410 ms | 0.3901% |
| Branch-and-Bound | 7/7 | 48.970 ms | 0.3486% |
| CP-SAT | 7/7 | 51.796 ms | 0% |
| Treewidth DP/fallback | 7/7 | 1.431 ms | 0.3901% |
| Portfolio | 7/7 | 43.490 ms | 0% |

이는 실제 서비스 latency 결과가 아니라 스케줄러 단위시험이다. 실제 OpenAI·지도 API의 tail latency, 429, 네트워크 변동을 포함한 온라인 A/B 시험이 필요하다.

# 17. 안전·생활편의 분석

## 17.1 반경

- 안전시설 기본 반경: 300m
- 생활편의 기본 반경: 500m

UI에는 반드시 “주변 몇 m 기준”인지 표시한다.

## 17.2 공간 집계

위도·경도가 있는 CSV는 bounding box로 1차 축소하고 Haversine으로 정확 반경을 판정한다. 주소만 있는 경찰·소방 데이터는 지오코딩 캐시를 사용한다.

공공데이터가 없을 때:

1. 생성된 공식 캐시
2. Naver local 검색
3. Kakao fallback
4. 모두 실패하면 조회불가

순으로 처리한다. 조회불가를 0개로 표시하지 않는다.

## 17.3 안전 휴리스틱

현재 가중치:

| 항목 | 단위 가중치 |
|---|---:|
| CCTV | 1 |
| 비상벨 | 2 |
| 경찰시설 | 15 |
| 소방시설 | 10 |
| 편의점 | 3 |

## 18.1 감사 스키마

각 실행은 UUID `decision_run_id`를 갖는다.

```text
decision_run
 ├─ 입력 스냅샷
 ├─ 코드·데이터·모델 버전

 ├─ risk/forecast/simulation
 ├─ synthesis

```

입력·출력은 JSON과 SHA-256 digest로 저장된다. API 키·token·secret·authorization·password 및 `sk-` 문자열은 `[REDACTED]`로 바뀐다.

## 18.2 “왜 이 집인가?”

UI는 감사데이터를 사람이 읽을 수 있는 근거트리로 재구성할 수 있다.

```text
매매 가능 판단
├─ 자기자금: 8,000만원
├─ 증여 예정액: 2,000만원
├─ 선택 상품 공개한도: 16,000만원
├─ 계약·부대비용 포함 필요금액: 27,120만원
├─ 월 상환제약: 통과
└─ 결론: 초기 현금 1,120만원 부족
```

언어모델의 문장이 아니라 저장된 계산항을 근거로 만든다.

## 18.3 장애 격리

상세 리포트의 독립 섹션은 병렬 실행하며 `allSettled` 방식으로 일부 실패를 격리한다. 예를 들어 뉴스 LLM이 실패해도 실거래 그래프, 안전시설, 자산 시뮬레이션은 반환해야 한다. 각 섹션은 상태 `ok`, `degraded`, `unavailable`과 사유를 갖는다.

## 18.4 보안 경계

- 외부로부터 받은 SQL은 읽기 전용 검증 후 실행.
- 비밀키는 환경변수.
- 서비스 로그에 프롬프트 원문과 개인정보를 무제한 저장하지 않음.
- 웹 검색결과의 지시문은 데이터로 취급하고 시스템 명령으로 실행하지 않음.
- 원격 HTML을 그대로 UI에 주입하지 않음.
- 주소·소득·자산은 최소한으로 수집하고 보존기간 정책이 필요.

## 19.2 지도 밀집도

모든 마커에 긴 전세·월세 라벨을 붙이면 지도를 가린다. 줌 수준별 표현을 사용한다.

- 광역: 클러스터 수와 대표 가격대
- 중간: 거래유형 색상 + 축약 가격
- 근접: 선택 마커만 상세 가격
- 하단 카드: 방·면적·층·관리비·위험 요약

점만 표시하지 않고 색·형태·숫자로 상태를 전달하되, 텍스트가 지형을 가리지 않게 한다.

## 19.3 필터 상호작용

- 초기조건은 하나의 노란 요약칩.
- 승인된 AI 조건은 별도 색상과 출처 표시.
- iPhone long-press로 추가필터 삭제.
- 초기조건은 편집 가능하되 전체 검색우주를 재계산.
- 빈 입력은 칩을 만들지 않음.

## 19.4 수치 설명

숫자를 나열하지 않고:

- 계기판: 집값 전망
- 도넛+표정: 뉴스 긍정/중립/부정
- 부채꼴: 자산 P10~P90
- 워터폴: 초기자금 구성
- 막대: 주변시설 개수와 반경
- 신호등 카드: 자격 pass/fail/unknown

를 사용한다. “어떻게 구하나요?”를 누르면 수식·입력값·가정을 펼친다. 내부 변수명이나 모델 파일명은 기본 UI에서 숨기고 감사 상세에서만 제공한다.

## 19.5 로딩과 중복응답

장시간 작업은 애니메이션 로딩을 보여주되 접근성용 텍스트와 취소·timeout을 제공한다. 동일 요청 ID를 중복 전송하지 않고, 서버도 idempotency/session 상태로 같은 챗봇 답변이 두 번 붙는 현상을 방지한다.

# 20. 실험과 검증

## 20.1 현재 검증된 것

| 영역 | 검증 |
|---|---|
| 집값 전망 | walk-forward 모델 비교 + conformal coverage |
| 임대인 자산 하위모형 | 시간분할 단위수·보증금·건물가 평가 |
| 선순위 하위 보증금 | 시간/공간 분할 quantile 평가 |
| 스케줄러 | 7개 합성 DAG makespan·계획시간 |
| SQL | 허용/거부·slot coverage 단위시험 |
| 시뮬레이션 | seed 재현, 분위수, 스트레스 단위시험 |
| 최적화 | 제약·파레토·MILP/fallback 단위시험 |
| API/UI | FastAPI와 모바일 viewport 회귀시험 |

## 20.2 검증되지 않은 것

- 실제 팔달구 건물별 선순위보증금 총합
- 특정 임대인의 실제 총자산
- 보증사고 이전모형의 팔달구 개별 계약 calibration
- 안전·편의 휴리스틱과 실제 범죄·생활만족의 관계
- 추천이 청년의 실제 의사결정을 개선하는지에 대한 사용자 연구
- 실시간 매물 재고의 정확도와 삭제·중복률
- 전국 지역·농어촌·도서지역 외삽
- 장기 생애자산 확률분포의 개인 수준 calibration

## 20.3 에이전트 평가 설계

150개 이상의 골든 질문에 다음을 라벨링한다.

1. 의도
2. 슬롯과 비교연산자
3. 질문 필요 여부
4. 기대 SQL 의미
5. 기대 결과 ID
6. 근거문장
7. 허용 fallback

지표:

$$
\text{Intent Accuracy}=\frac{\#\text{correct intent}}{N}
$$

조건추출은 field/value/operator 단위 micro-F1을 쓴다.

검색:

$$
\text{Recall@k}
=\frac{|R_k\cap G|}{|G|}
$$

생성:

- faithfulness: 근거가 뒷받침하는 주장 비율
- answer relevance
- unsupported numeric claim rate
- 자격판정 정확도
- SQL 실행성공률
- 부적절 조건생성률
- fallback 복구율
- P50/P95 latency
- 요청당 token·API 비용

RAGAS 계열 지표는 보조 자동평가로 쓸 수 있지만, 금융·주거의 수치·자격은 결정적 정답검사와 전문가 검토가 우선이다.

## 20.4 추천 오프라인 평가

역사적 시점 $t$에서 당시 가용 데이터만 사용하고 이후 실거래·금리·생활비를 결과로 둔다. look-ahead leakage를 막는다.

- feasible recommendation rate
- constraint violation rate
- Pareto coverage
- regret against hindsight optimum
- diversity across region/type/transaction
- preference consistency
- 위험 상위군 calibration

## 20.5 사용자 연구 제안

무작위 교차 설계:

- A: 일반 필터 검색
- B: 설명 없는 AI 추천
- C: 본 시스템의 근거·불확실성 추천

과업은 적합 매물 찾기, 금융상품 판정, 위험요인 찾기, 전세·월세 비교다. 측정값은 정확도, 시간, 인지부하, 신뢰 calibration, 설명 이해도, 과신률이다. 단순 만족도만으로 성능을 주장하지 않는다.

# 23. 성능 병목과 운영

## 23.1 주요 병목

1. 외부 LLM 네트워크 왕복과 재시도.
2. 지도·대중교통 경로 API의 tail latency.
3. 931,929개 가격관측과 220열 매물 스키마를 반복 조회하는 비효율 SQL.
4. 상세 리포트의 뉴스·시설·시계열·시뮬레이션 직렬 실행.
5. 최초 지오코딩과 대형 CSV 파싱.

몬테카를로 10,000 경로 자체는 벡터화되어 있으며 보통 LLM보다 작은 병목이다.

## 23.2 완화

- DB 인덱스와 필요한 열만 SELECT.
- 공공시설을 메모리/공간 인덱스로 캐시.
- 목적지 지오코딩 캐시.
- 초기 SQL 교집합 뒤 경로 API 최대 5건.
- 독립 리포트 섹션 병렬 실행.
- LLM semaphore 기본 6.
- 조건 SQL worker 기본 2.
- timeout 후 부분결과 반환.
- seed가 같은 시뮬레이션 입력 캐시.
- 오래된 외부 데이터에는 freshness 표시.

## 23.3 양자화 로컬 LLM

로컬 양자화는 네트워크 지연과 호출비를 줄일 수 있지만:

- Text-to-SQL·JSON 정확도 저하 가능
- 한국어 금융용어 이해 검증 필요
- 서버 GPU/CPU 병목
- 모델 로딩 메모리

가 생긴다. 본 구조에서는 Planner와 합성만 작은 로컬 모델로 교체할 수 있고, 계산기는 그대로 유지된다. 동일 골든셋에서 정확도·P95·비용을 비교한 뒤 선택해야 한다.

## 23.4 AWS Lightsail 배포

현재 배포형태는 서울 리전의 AWS Lightsail 단일 인스턴스, Docker
Compose, Nginx reverse proxy, FastAPI 컨테이너다.

```text
Internet
 → Lightsail static IPv4
 → Nginx :80/:443
 → FastAPI/Uvicorn :8000
 → SQLite volume + model/data volumes
```

재현 절차:

```bash

cd /opt/jeonse-helper
git clone https://github.com/minjaechoics/KB-HouseAgent.git .
# 서버에서만 .env.production 및 필요한 private.env 작성
```

전송하거나 서버에서 재생성한다. 공개 전에는 고정 IP HTTP가 아니라
도메인, TLS, 최소 방화벽, 로그 마스킹, 자동 백업, 디스크 모니터링,
healthcheck, rollback 가능한 이미지 태그가 필요하다. 과거 문서의 Basic
인증 설정은 현재 제품 요구에서 제거되었으므로 이를 개인정보 보호수단으로
간주해서는 안 된다.

# 27. 결론

KB HouseAgent의 핵심은 화려한 한 문장의 추천이 아니다. 자연어 목표를 관계형 조건으로 바꾸고, 정확한 교집합을 검색하며, 금융상품·위험·통근·장기자산을 독립된 계산기로 평가하고, 그 근거를 한 실행 ID 아래 재현하는 구조다.

현재 프로토타입은 다음을 실제로 구현한다.

- JSON 구조의 Planner와 안전한 Text-to-SQL
- 팔달구 매물·금융상품 RDB 검색
- Naver/TMAP 경로 도구와 호출 상한
- 전세보증 사고 이전모형
- 임대인 자산·선순위보증금·전세가율 확률모형
- walk-forward·conformal 집값 전망
- 10,000경로 생애자산 시뮬레이션
- 파레토/MILP 추천
- 작업 DAG 스케줄링
- 공공시설 반경 집계
- 결정 실행 감사

동시에 특정 임대인의 실제 자산, 법률상 선순위 총액, 실시간 매물, 지역별 실제 보증사고 calibration은 아직 확보되지 않았다. 이 사실을 결과에서 명확히 드러내는 것이 시스템의 약점이 아니라 신뢰성의 출발점이다. 향후 연구는 더 큰 모델보다 더 좋은 라벨, 시간순 외부검증, 사용자 연구, 데이터 권리와 개인정보 보호에 우선순위를 두어야 한다.
